# 老品下滑归因诊断

## Purpose

严格按照《亚马逊老品下滑整改闭环 SOP 文档》(V1.0) 执行归因诊断：
- 自动从广告系统发现近期下滑的 SKU（7天 vs 30天日均订单对比）
- 按 SOP 产品分级规则判定（核心/边缘/淘汰/潜力）
- 按归因矩阵锁定 1-2 项核心根因（每项有数据依据）
- 匹配标准化整改动作包
- 输出完整的《老品整改问题单》

## When To Run

用户提到以下任一关键词时触发：
- "老品归因"
- "帮我归因"
- "SKU 为什么下滑"
- "老品下滑分析"
- "整改问题单"
- "老品诊断"
- "下滑原因"
- "哪些SKU在下滑"
- "帮我看看 SKU XXX"

## Prerequisites

脚本会自动处理所有环境，零操作门槛：

1. **ws 依赖** — 首次运行自动安装
2. **Chrome debug 模式** — 未启动则自动启动（端口 9222）
3. **后台登录** — 未登录的系统会自动打开并通过企业微信快捷登录（"继续在浏览器中登录访问"按钮自动点击）：
   - adv.yswg.com.cn（广告数据 — 必须）
   - sif.com（前台流量 — 可选，30秒内未完成则跳过）
   - sellerinventory.yswg.com.cn（同比数据 — 可选，30秒内未完成则跳过）

唯一前提：电脑装了 Chrome 和 Node.js，且企业微信桌面端已登录。

## Workflow

### 模式1：自动发现（推荐，无需任何输入）

```powershell
node "<skill-dir>/scripts/diagnose.js"
```

流程：
1. 自动获取当前登录账号的销售编号
2. 从广告系统拉取全量 SKU 的 30天 + 7天数据
3. 比对找出订单显著下滑的 SKU（7天日均 vs 30天日均降幅>20%）
4. 对 top 5 下滑 SKU 逐个诊断并输出问题单
5. 最后给出汇总表

### 模式2：指定SKU诊断

```powershell
node "<skill-dir>/scripts/diagnose.js" --sku <SKU>
```

### 参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| --sku | 指定诊断的SKU（不传则自动发现） | 自动 |
| --seller | 手动指定销售编号（逗号分隔） | 自动从浏览器获取 |
| --top | 自动发现模式下诊断前N个下滑SKU | 5 |

其中 `<skill-dir>` 是本 skill 的安装位置，通常为：
- 本项目内：`D:\ad-ops-workbench\.codex\skills\old-product-decline-diagnosis`

## Output Contract

脚本输出为标准化的《老品整改问题单》，格式固定，包含：
- SKU/ASIN
- 产品分级
- 表层指标变化（销量、ACoS、转化率、点击率、展现量）
- 核心根因（1-2 项）+ 数据依据
- 匹配整改动作 + 验证指标
- 整改周期、风险等级

自动发现模式额外输出：
- 下滑 SKU 列表（按订单降幅排序）
- 所有诊断结果汇总表

直接将脚本输出展示给用户即可，不需要二次加工。

## Red Lines

- 不得编造数据——所有数据必须来自后台实际拉取
- 不得直接执行任何广告/库存/价格操作
- 根因不超过 2 项，每项必须有数据支撑
- 如果后台未登录或数据拉取失败，明确告知用户，不要猜测
