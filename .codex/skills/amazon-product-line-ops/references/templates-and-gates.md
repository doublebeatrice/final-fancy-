# 模板与门控

当用户需要表格、SOP 输出、门控评审或具体执行计划时，读取本文件。

## 1. 产品线方向卡

| 字段 | 填写内容 |
|---|---|
| 目标用户 | 具体用户群，不要只写泛人群 |
| 核心问题 | 高频、明确、可购买解决方案的问题 |
| 产品线边界 | 哪些产品属于本产品线，哪些不属于 |
| 获胜能力 | 供应链、设计、内容、广告、价格、合规、包装、服务 |
| 首个 SKU 角色 | 入口款、利润款、升级款、防守款、复购款、礼品款、套装款 |
| 资源约束 | 预算、供应商、设计、合规、Review 壁垒、交期 |
| 不做清单 | 至少 5 条明确不碰的机会 |
| 门控结论 | Go / Validate / Hold / No-Go |

## 2. 市场雷达

| 维度 | 需要收集的证据 | 红灯信号 |
|---|---|---|
| 需求 | 核心词、属性词、场景词、痛点词、竞品词 | 一个大词承载大部分需求 |
| 流量 | SERP 多样性、非品牌词、长尾入口 | 头部品牌锁死高意图词 |
| 竞争 | Review、价格、页面质量、视觉质量、A+教育 | 低价 + 高评论 + 成熟页面 |
| 内容低效 | 说明书弱、对比弱、规格不清、图片差 | 看不到明显低效 |
| 广告 | Sponsored 位置、CPC 估算、PT 机会 | 流量贵且毛利承受不了 |
| 资金 | 价格带、费用、coupon、FBA、补货现金 | 低价竞争击穿现金流 |

门控结论格式：

```text
结论：Go / Validate / Hold / No-Go
理由：
证据：
风险：
下一步补证据：
负责人和期限：
```

## 3. 节点评分卡

| 字段 | 含义 |
|---|---|
| 节点名称 | 用户任务 + 商品集 + 价格带 |
| 搜索入口 | 大词、属性词、场景词、痛点词、替代方案词 |
| 商品集 | 产品形态和用户任务接近的一组产品 |
| 代表 ASIN | 去重后的父/子/变体证据 |
| 价格结构 | 低/中/高价格带及销量集中度 |
| Review 壁垒 | 评论数量、评分、差评模式 |
| 页面弱点 | 主图、附图、A+、视频、FAQ |
| 供应适配 | 供应商是否能做出定义中的产品 |
| 合规风险 | 认证、宣称、安全、标签、受限类目 |
| 经济性 | 毛利、CPA 容忍、补货现金 |
| 门控 | P1/P2/P3/排除 或 Go/Validate/Hold/No-Go |

硬性打回信号：

- 没有锚定 ASIN。
- 只有一个大词入口。
- 价格和利润无法覆盖广告与 coupon。
- 合规风险不清。
- 供应链无法承接产品定义。
- 现金无法支撑首批和补货。

## 4. 5D 词库字段

| 字段 | 用途 |
|---|---|
| 关键词 | 原始词 |
| 词根 | 可复用的词根/词簇 |
| 意图类型 | 品类词、属性词、场景词、痛点词、品牌词、噪音词 |
| 相关性 | 高 / 中 / 低 / 冲突 / 无关 |
| 购买强度 | 高 / 中 / 低 |
| 竞争压力 | 高 / 中 / 低 |
| 利润承受 | CPC/CPA 是否能落入毛利边界 |
| 时间价值 | 常青、季节、节日、趋势、生命周期 |
| 页面路由 | 标题、五点、A+、后台词、图片、FAQ、不使用 |
| 广告路由 | Auto、Broad、Phrase、Exact、PT、防守、测试、不投 |
| 否词路由 | 否定 exact、否定 phrase、隔离、观察 |
| 证据 | 搜索、竞品、Review、报表、人工判断 |

规则：进入标题前部、Exact 攻击或核心视觉表达的词，必须同时具备高相关、产品能承接、利润有边界、证据能支持。

## 5. 竞品库

竞品分类：

- 直接竞品：同商品集、同用户任务。
- 替代竞品：用不同方式解决同一任务。
- 学习竞品：页面、视觉、组合、教育或定价模型值得学习。
- 广告竞品：出现在目标广告战场，即使产品不同也要观察。

每条竞品记录必须反哺至少一个动作：

- 改产品
- 改价格
- 改主图/附图/A+
- 改文案、FAQ 或边界说明
- Product Targeting 攻击或避让
- Store 路径或套装思路
- 否定关键词/ASIN 排除

## 6. VOC 翻译

| VOC 证据 | 翻译成 |
|---|---|
| 重复抱怨 | 产品参数、说明书、包装、FAQ、警示 |
| 用户原话 | 五点表达、图片 headline、A+段落、广告语 |
| 误用或困惑 | 步骤图、视频、包装标签、客服脚本 |
| 正向场景 | 场景图、Store 路径、套装、关联 SKU |
| 退货原因 | 产品边界、尺寸/规格修正、页面承诺调整 |

不要把夸张用户语言直接搬进 Listing。要转成合规、可证明、有证据支撑的表达。

## 7. 产品定义 / RFQ

最少字段：

- 用户任务与使用场景
- 核心功能
- 产品形态与组件
- 材质/成分/规格
- 尺寸、容量、兼容、颜色、数量
- 安全/合规边界
- 包装和说明书要求
- 品质/测试要求
- 成本、MOQ、交期、样品、认证、验货要求

门控：如果产品定义还不能支撑供应商打样、设计脚本、广告战场选择和客服边界，就不要进入 RFQ 或 Listing。

## 8. 文案、视觉、包装一致性

检查所有资产是否表达同一组事实：

- 标题和五点
- 属性和后台字段
- 主图和附图
- A+ 模块
- 视频
- 包装正反面
- 说明书
- FAQ/Q&A 与售后脚本

打回这些资产：

- 承诺了产品无法证明的结果。
- 隐藏兼容、尺寸、数量、材质或使用限制。
- 图片宣称没有产品定义支持。
- 合规敏感宣称没有当前政策/法务依据。

## 9. Day 0 上线准备门控

上线前检查：

- Listing 已上线且内容正确。
- Featured Offer/Buy Box 状态正常。
- sale price/coupon 生效并在毛利边界内。
- FBA/库存状态和补货计划正常。
- 广告已启用，预算、bid、匹配方式、placement、命名正确。
- Vine/Creator/样品追踪已准备，且符合当前规则。
- 日监控表、负责人、升级规则和动作日志已准备。
- 风险红线已按当前 Seller Central / Amazon Ads 规则复核。
