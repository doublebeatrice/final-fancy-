# 亚马逊产品线全链路作战总纲

当用户要求“帮我梳理这个产品”“这个产品应该怎么做”“我把数据都发给你，你来判断”“上架前后怎么执行”“运营哪里有问题”时，读取本文件。

本文件的作用不是复述手册，而是把手册底层逻辑变成可执行的产品与运营诊断流程。默认原则：先建立证据链，再做判断；先判断产品和市场，再判断页面、广告和促销；先识别数据置信度，再决定动作。

## 0. 使用边界

### 0.1 来源标签

输出结论时尽量标注来源类型：

| 标签 | 含义 | 用法 |
|---|---|---|
| 资料已有 | 手册明确提出或强支撑 | 用于核心方法、门控、流程、诊断原则 |
| 资料提到但不足 | 手册提到方向，但实操细节需要展开 | 用于字段、表格、动作规则、案例解释 |
| 资料未提到，建议补充 | 真实运营需要，但手册覆盖不足 | 用于平台后台字段、工具表结构、类目特殊规则 |
| 不确定，需要进一步查证 | 依赖最新政策、后台功能或类目规则 | 用于 Amazon 政策、费用、资格、广告新功能 |

### 0.2 不要做的事

- 不要只根据一个大词搜索量判断市场能做。
- 不要只根据一个热卖 ASIN 判断产品能做。
- 不要只根据卖家精灵销量或关键词排名选择竞品。
- 不要把 Listing、广告、coupon 当作弥补产品定义错误的工具。
- 不要用当天 ACOS、低样本 CVR 或归因期内数据做激进决策。
- 不要同时大改价格、coupon、主图、广告 bid、页面文案，否则无法归因。
- 不要在库存、现金、合规、Review 风险未过门控时盲目放量。

## 1. 总体工作流

收到产品、图片、ASIN、关键词、卖家精灵表、广告报表、Listing 或一批杂乱资料后，按下面顺序工作。

```text
资料盘点
-> 产品识别
-> 标品/非标品/半标品判断
-> 市场与节点判断
-> 竞品池清洗与分层
-> VOC/Review/Q&A 提炼
-> 5D 词库与路由
-> 产品定义与 SKU 角色
-> 定价/coupon/毛利/现金测算
-> Listing 文案、视觉、A+、包装一致性
-> 广告结构与上线准备
-> Day 0-D90 经营诊断
-> 周会复盘、扩品或 Go/Pivot/Kill
```

任何一步证据不足时，不要停止。先输出“暂定判断”，再列出最少补证据清单和人工确认表。

## 2. 资料盘点与数据置信度

### 2.1 先做文件清单

当用户把资料都发来时，先整理：

| 文件/资料 | 初判类型 | 可识别字段 | 日期/站点 | 可用于什么 | 问题 |
|---|---|---|---|---|---|
| 产品图片/链接 | 产品识别 | 形态、颜色、组件、场景 | 待确认 | 判断标品/非标品、竞品相似度 | 图片角度是否完整 |
| 卖家精灵市场表 | 市场 | 搜索量、竞品数量、趋势 | 必须记录 | 市场入口、节点判断 | 字段是否来自同一站点 |
| 竞品表 | 竞品 | ASIN、价格、Review、评分、销量 | 必须记录 | 竞品池、价格带、壁垒 | 是否混入不同商品集 |
| 关键词表 | 词库 | keyword、SFR/ABA、CPC、排名 | 必须记录 | 词库、广告、Listing | 相关性需人工确认 |
| 广告报表 | 广告 | 花费、点击、订单、ACOS、搜索词 | 必须记录 | 投放诊断 | 归因窗口和样本量 |
| 成本/报价 | 财务 | 成本、头程、FBA、佣金、MOQ | 必须记录 | 毛利、CPA 边界 | 费用是否最新 |
| 库存/补货 | 供应 | 库存、在途、交期、现金 | 必须记录 | 放量门控 | 缺现金流数据 |
| Review/VOC | 用户 | 差评、痛点、场景、质量问题 | 必须记录 | 产品和页面修复 | 样本是否偏头部竞品 |

### 2.2 数据置信度

每个结论必须带置信度：

| 置信度 | 判断标准 | 适合动作 |
|---|---|---|
| 低 | 样本少、字段缺、日期旧、归因未完成、产品相似度不明 | 只做假设，不做大投入 |
| 中 | 字段基本完整，有多个来源互证，但仍需人工确认 | 可做小预算测试和页面修复 |
| 高 | 跨来源、跨周期重复出现，产品/价格/页面/库存状态稳定 | 可进入 Go、放量或结构调整 |

## 3. 产品识别

### 3.1 先用图片和链接判断

如果有产品图，优先从视觉识别：

- 产品是什么品类。
- 单品、套装、补充装、配件、消耗品还是升级款。
- 主要材质、颜色、形状、结构、尺寸感。
- 随货组件、包装形态、使用场景。
- 是否偏功能参数购买，还是偏风格/审美/场景购买。
- 可能合规风险：儿童、食品接触、电池、医疗、美妆、安全、化学、商标、专利。

### 3.2 判断标品、非标品、半标品

竞品分析前必须先判断产品类型。

| 类型 | 用户购买逻辑 | 竞品选择优先级 | 常见错误 |
|---|---|---|---|
| 标品 | 参数、型号、兼容、认证、功能决定购买 | 用途一致 > 参数一致 > 价格带接近 > Review 壁垒 > 页面弱点 | 只看图片像，不核对规格 |
| 非标品 | 外观、风格、场景、材质、套装、人群决定购买 | 图片形态相似 > 场景相似 > 人群相似 > 风格材质接近 > 价格带 | 只按关键词/销量抓竞品 |
| 半标品 | 参数和视觉都影响购买 | 参数一致 + 图片相似 + 场景一致 | 一刀切按标品或非标品分析 |

输出必须包含：

```text
产品类型判断：
判断依据：
竞品筛选优先级：
需要人工确认：
```

## 4. 市场与节点判断

### 4.1 市场不是大词

大词只能证明需求存在，不能证明新品能进入，也不能证明利润能成立。市场要拆成节点：

- 人群节点：谁在买。
- 场景节点：什么时候、在哪里、为了什么任务买。
- 规格/材质节点：尺寸、容量、材质、成分、兼容、结构。
- 套装/补充装节点：单品、组合、替换装、补充包。
- 使用周期节点：一次性、消耗型、周期补货、长期使用。
- 价格带节点：低价、中价、高价的销量和销售额结构。
- 替代方案节点：用户如果不买这个，会买什么。

### 4.2 结构性低效

值得进入的市场通常不是“没人做”，而是“有人买，但现有卖家承接得不够系统”。

| 低效类型 | 怎么识别 | 能转成什么动作 |
|---|---|---|
| 搜索入口低效 | 长尾词、属性词、场景词丰富，头部只守大词 | 词库分层，避开硬拼大词 |
| 页面低效 | 主图不清、附图不解释、A+弱、FAQ缺 | 主图重构、A+教育、FAQ补强 |
| 产品形态低效 | 规格、组件、使用方式、兼容边界不清 | 产品定义、包装、说明书改进 |
| 价格带低效 | 中高价缺价值证明，低价牺牲质量 | 价值表达或避开错误价格带 |
| 用户教育低效 | 用户不知道怎么选、怎么装、怎么用 | 对比图、步骤图、视频、说明书 |
| 广告战场低效 | 竞品只打大词，不打长尾/PT/类目 | 长尾 exact、ASIN PT、类目测试 |
| 包装说明低效 | 到手体验差、误用多、差评集中 | 包装、说明书、售后流程 |
| 产品线低效 | 单品孤立，没有关联路径 | Store、组合款、补充装、升级款 |

### 4.3 市场门控

| 结论 | 条件 | 动作 |
|---|---|---|
| Go | 多入口需求、竞品有低效、产品能差异、毛利和供应可承接 | 进入产品定义和上架准备 |
| Validate | 有机会但缺关键证据 | 补 ASIN、关键词、VOC、成本、合规、广告成本 |
| Hold | 机会暂时看不清，或现金/供应暂不允许 | 建观察清单，不投入核心资源 |
| No-Go | 单一大词、头部强锁定、低价击穿、合规/供应不可承接 | 记录反向学习，转节点 |

## 5. 竞品池与 ASIN 证据

### 5.1 ASIN 池不是结论

ASIN 池只是证据层。它用于识别商品集、价格带、搜索入口、用户任务和竞品格局，不能直接拿“销量最高的 ASIN”当开发方向。

### 5.2 必须清洗

清洗规则：

- 父 ASIN、子 ASIN、变体家族分开记录，避免重复放大市场。
- 套装、补充装、配件、主产品分开标注。
- 不同使用任务的产品不能混入同一商品集。
- 不同规格/兼容/材质导致购买决策不同的，要拆开。
- 价格和 coupon 会变，必须记录抓取日期。
- 标记直接竞品、替代竞品、学习竞品、广告竞品、避让竞品、剔除样本。

### 5.3 竞品分层

| 层级 | 定义 | 主要用途 |
|---|---|---|
| 直接竞品 | 用户会拿来直接比较，产品形态/参数/场景相近 | 价格、Review、页面、广告重点拆 |
| 替代竞品 | 解决同一任务但产品形态不同 | 理解用户替代选择和价格锚点 |
| 学习竞品 | 页面、视觉、A+、组合、品牌表达优秀 | 学习表达，不一定正面打 |
| 广告竞品 | 出现在核心广告位、竞品页或类目广告位 | PT、类目、竞品页策略 |
| 避让竞品 | 评论壁垒、品牌势能、低价优势过强 | 避免硬碰硬 |
| 剔除样本 | 形态、规格、场景、用户任务不一致 | 不进入核心分析 |

## 6. VOC、Review 与用户画像

### 6.1 VOC 的作用

VOC 不是“找几个痛点写进五点”，而是把用户语言翻译成产品、页面、包装、说明书、广告和售后动作。

### 6.2 六问画像

| 问题 | 需要输出 |
|---|---|
| Who | 谁买、谁用、谁决策 |
| When | 什么时候触发购买 |
| Where | 在什么场景使用 |
| What | 具体要完成什么任务 |
| Why | 为什么选择这一类产品 |
| Objections | 为什么犹豫、退货、差评 |

### 6.3 VOC 到动作

| VOC 信号 | 可能含义 | 运营动作 |
|---|---|---|
| 尺寸/兼容抱怨 | 页面没讲清或产品边界错 | 附图、FAQ、标题/五点边界、说明书 |
| 安装/使用困难 | 教育不足 | 步骤图、视频、说明书、包装内卡 |
| 材质/质量差评 | 产品事实或期望错位 | 产品改款、主图和文案降承诺 |
| 包装破损 | 到手体验和退货风险 | 包装结构、质检、物流测试 |
| 效果不符合预期 | 宣称过强或用户场景不匹配 | 文案合规、场景收窄、广告否词 |
| 喜欢某个竞品功能 | 商品集共性或差异机会 | 产品定义/RFQ 加入验证 |

## 7. 5D 词库与路由

### 7.1 词库不是堆词

合格词库要回答：

- 词有没有商业价值。
- 和产品是强相关、中相关、弱相关、冲突还是无关。
- 属于品类词、属性词、场景词、痛点词、品牌词、噪音词。
- 应该进标题、五点、A+、后台词、图片、FAQ、广告还是否词。
- 是否能被产品事实、页面承诺和毛利承接。
- 是常青词、季节词、节日词、趋势词还是生命周期词。

### 7.2 词库路由表

| 词类型 | 页面路由 | 广告路由 | 风险 |
|---|---|---|---|
| 核心品类词 | 标题前部、主图身份 | Exact/Phrase，小心 CPC | 竞争贵，不能空泛承接 |
| 属性规格词 | 五点、附图、后台属性 | Exact/Phrase | 必须与产品事实一致 |
| 场景人群词 | 附图、A+、视频 | Phrase/Broad 测试 | 场景不符会低 CVR |
| 痛点词 | 五点、A+、FAQ | Phrase/Exact 小预算 | 不能做过度承诺 |
| 竞品词/ASIN | 不写入 Listing | PT/合规边界内广告 | 商标和品牌词风险 |
| 噪音/冲突词 | 不使用 | 否词/排除 | 浪费广告、误导页面 |

### 7.3 人工复核

重点复核三类词：

- 看似相关实则产品形态不同。
- 高搜索但广告成本和毛利不匹配。
- 品牌词、功效词、医疗/安全/绝对化表达等高风险词。

## 8. 产品定义、SKU 角色与 RFQ

### 8.1 产品定义先于 Listing

标题、五点、主图、A+ 不应该靠文案临时编卖点，而应该从产品定义自然长出来。

### 8.2 九字段定义

每个产品进入 RFQ 前，至少写清：

| 字段 | 要说明什么 |
|---|---|
| 用户 | 谁买、谁用、谁决策 |
| 场景 | 在什么场景完成什么任务 |
| 产品形态 | 单品、套装、配件、补充装、升级款 |
| 功能机制 | 为什么能解决问题 |
| 规格参数 | 尺寸、容量、数量、兼容、型号、成分 |
| 材质/结构 | 材质、结构、工艺、耐用性、安全边界 |
| 差异点 | 比直接竞品强在哪里 |
| 价格带 | 目标售价、到手价、coupon、毛利边界 |
| 风险边界 | 合规、认证、专利、质量、退货、误用 |

### 8.3 SKU 角色

| 角色 | 任务 | 判断依据 |
|---|---|---|
| 入口款 | 获取高相关流量 | 搜索词和广告词能带来流量 |
| 标准款 | 站在主流需求里 | 竞品销量结构和价格带 |
| 利润款 | 承接更高毛利 | 贡献毛利、CPA 容忍度、退货风险 |
| 升级款 | 解决更复杂需求 | VOC、教育成本、视频/A+承接能力 |
| 防守款 | 防守竞品或替代方案 | 竞品 ASIN、关联购买、Store 路径 |
| 复购/补充款 | 提升生命周期价值 | 使用周期、耗材、补货需求 |

### 8.4 RFQ 不是问最低价

RFQ 要验证供应链是否能实现产品线假设。至少包含规格、组件、材质、包装、认证、质检、MOQ、交期、可改款空间、成本阶梯、样品要求、风险测试。

## 9. 定价、coupon、预算与现金

### 9.1 价格是测试区间

不要把价格当固定组合。要同时看：

- List price、sale price、coupon。
- 用户实际到手价。
- 竞品价格带和 Review 壁垒。
- 贡献毛利。
- CPA/CPC 容忍度。
- 库存周转和补货现金。

### 9.2 核心公式

| 指标 | 作用 |
|---|---|
| 广告前贡献毛利 | 判断广告之前一单剩多少钱 |
| Breakeven CPA | 每单最多能花多少广告费不亏 |
| Breakeven CPC | 在预期 CVR 下每次点击最多能花多少 |
| TACOS | 判断广告对整体销售和利润的压力 |
| coupon 核销率 | 判断优惠是否真正促进购买 |

公式必须结合站点、佣金、FBA、头程、coupon 规则、退货率、费用表校准。

### 9.3 库存、广告、现金联动

| 状态 | 含义 | 动作 |
|---|---|---|
| 库存绿 + 现金绿 | 可承接增长 | 可以测试放量 |
| 库存黄 | 有断货风险 | 控预算，优先稳排名和利润 |
| 库存红 | 放量会断货 | 停止扩量，处理补货 |
| 现金黄 | 补货和广告争资金 | 降低探索预算，保留验证/收割 |
| 现金红 | 无法承接亏损测试 | 停止大额测试，优先回款和库存 |

## 10. Listing、视觉、A+、包装一致性

### 10.1 页面双重任务

- 让平台知道你是什么：品类身份、属性、规格、搜索相关性。
- 让用户相信为什么买你：场景、机制、对比、证据、风险边界。

### 10.2 文案结构

| 位置 | 核心任务 |
|---|---|
| 标题 | 产品身份 + 核心高相关词 + 关键规格/属性 |
| 五点 | 结果、机制、场景、规格、信任边界 |
| A+ | 教育、对比、场景叙事、品牌信任 |
| 后台词 | 相关但不适合前台重复的词 |
| FAQ | 兼容、尺寸、安装、使用限制、常见顾虑 |

### 10.3 视觉脚本

| 资产 | 检查重点 |
|---|---|
| 主图 | 移动端能识别品类、主体、规格、包装；和竞品有差异 |
| 附图 | 解释规格、场景、对比、使用步骤、到手组件 |
| A+ | 承接用户画像、痛点、教育、品牌信任 |
| 视频 | 解释使用、安装、效果边界、场景 |
| 包装 | 承接页面承诺，降低误用和差评 |
| 说明书 | 使用步骤、注意事项、售后入口、风险边界 |

### 10.4 一致性验收

页面、产品、包装、说明书、广告必须讲同一组事实。凡是页面承诺但实物、包装、说明书无法证明的内容，都要降低承诺或补证据。

## 11. 广告与上线

广告不是买词，而是选择战场和验证流量。广告结构必须对应不同任务：

| 任务 | 典型结构 | 目的 |
|---|---|---|
| 探索 | Auto、Broad、Category | 找真实搜索词和 ASIN |
| 验证 | Phrase、Exact、PT | 验证中高相关词/ASIN |
| 收割 | Exact、强 ASIN PT | 放大稳定转化目标 |
| 防守 | 品牌词、核心 ASIN、老品防守 | 防止被截流 |
| 修复 | 小预算测试 | 验证页面/价格修复效果 |

广告动作必须联动 CTR、CVR、CPC、CPA、ACOS、TACOS、coupon、库存、现金、Review、SQP/自然词，而不是只看 ACOS。广告深度动作读取 `references/advertising-optimization-playbook.md`。

## 12. Day 0-D90 经营

| 阶段 | 核心问题 | 看什么 | 不要做什么 |
|---|---|---|---|
| D0-D7 | 设置是否正确、流量是否相关 | Listing 状态、价格、coupon、库存、CTR、CPC、搜索词 | 用当天 ACOS 恐慌砍词 |
| D8-D30 | 页面和 offer 能否转化 | CVR、CPA、coupon 核销、Review/Q&A、主图/A+反馈 | 页面没修就放量 |
| D31-D60 | 模型能否扩大 | TACOS、自然单、SQP、排名、库存、现金 | 广告增长导致断货或现金紧张 |
| D61-D90 | 能否防守和扩展 | 核心词/ASIN、防守、coupon 退坡、促销、Store 路径 | 没产品线逻辑就扩 SKU |

## 13. 周会复盘

周会不是报数，而是把数据变成动作。固定输出：

| 模块 | 必看内容 | 输出 |
|---|---|---|
| 结果 | 销售、广告花费、ACOS/TACOS、毛利 | 本周结论 |
| 页面 | CTR、CVR、Review、Q&A、退货 | 修复动作 |
| 广告 | 搜索词、ASIN、bid、预算、否词、迁移 | 下周投放动作 |
| 自然 | 排名、SQP、自然单、转化词 | 页面/广告回流 |
| 价格/coupon | 领取、核销、CVR、CPA、毛利 | 是否调价/退坡 |
| 库存/现金 | 可售天数、在途、补货、现金 | 放量门控 |
| 竞品 | 价格、Review、广告位、主图变化 | 反制或学习 |
| 动作日志 | 上周动作、结果、回滚 | 保留/修改/停止 |

每个动作要写：动作、负责人、原因、执行日期、观察窗口、成功指标、回滚条件。

## 14. Brand Store 与产品线扩展

扩 SKU 前先确认单品不是偶然起量。扩展依据：

- 核心用户是否清楚。
- 搜索词和自然词是否能支持新 SKU。
- VOC 是否指向新规格、新场景、补充装或升级款。
- Store 路径是否能承接入口款到利润款/升级款/补充款。
- 库存、现金、供应链是否能承接复杂度。

不要因为一个 SKU 有销量就盲目扩品。产品线是角色分工系统，不是 SKU 堆叠。

## 15. Go / Fix / Hold / Pivot / Kill

不要在没有检查 setup、target、页面、价格、库存、现金、Review、产品事实前，直接判定产品失败。

| 决策 | 适用情况 |
|---|---|
| Go | 模型有效，库存和现金允许放量 |
| Fix | 问题明确，可通过页面、广告、价格、产品或运营修复 |
| Hold | 证据不足，或库存/现金/合规阻塞 |
| Pivot target | 流量、人群、关键词、ASIN 战场错 |
| Pivot page | 产品可能成立，但页面表达和信任不成立 |
| Pivot price | 价格带、coupon、毛利模型错位 |
| Pivot product | 产品事实无法满足关键需求 |
| Kill | 触发停止条件，继续投入会扩大损失 |

反向学习必须沉淀：

- 哪个关键词误导了我们？
- 哪个竞品样本选错了？
- 哪个用户画像不准确？
- 哪个产品参数没承接？
- 哪个页面承诺过强？
- 哪个广告战场不可赢？
- 哪个成本/现金假设过于乐观？

## 16. 合规与政策更新

所有涉及 Amazon 政策、费用、促销资格、Review/Vine、图片规范、广告功能、类目限制、功效宣称、认证要求的内容，都属于强时效内容。使用时必须：

1. 标明当前判断基于哪一天的资料。
2. 要求用户提供后台截图、政策链接或允许核对官方信息。
3. 用 `保留 / 修改 / 新增 / 删除或弃用 / 待查` 更新技能内判断。
4. 不把旧政策当作永远有效。

## 18. 最少人工确认清单

当用户想少填表时，只要求确认最关键内容：

| 模块 | 需要确认 |
|---|---|
| 产品 | 名称、站点、规格、成本、目标价格、图片/链接 |
| 产品类型 | 标品、非标品、半标品是否判断正确 |
| 竞品 | 哪些 ASIN 是真正相似竞品 |
| 关键词 | 哪些词产品能承接，哪些词绝对不能投 |
| 成本 | 产品成本、FBA、佣金、头程、coupon、退货预估 |
| 库存 | 首批数量、补货周期、在途、现金 |
| 合规 | 认证、专利、商标、类目、宣称风险 |

如果这些都没有，也可以先做“低置信初判”，但不能给最终 Go 结论。
