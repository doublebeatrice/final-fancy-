# 产品诊断剧本

当用户说“帮我梳理这个产品”“这个产品应该怎么做”“这个品能不能上”“帮我检查产品逻辑”时，读取本文件。

目标不是写泛泛建议，而是把一个产品梳理成可执行的亚马逊产品线经营方案。

## 一、最小信息收集

如果用户已经提供了产品、图片、ASIN、关键词表、Listing、广告数据、成本表或卖家精灵导出文件，先基于已有内容判断。缺失信息再补问，不要一开始问一大堆。

优先顺序：

1. 先看产品图/链接/样品描述，判断产品形态、关键属性和标品/非标品。
2. 再读卖家精灵导出数据，识别竞品、关键词、CPC、Review、价格等字段。
3. 再自动生成候选竞品和候选关键词。
4. 最后输出给用户人工确认，不要直接把自动候选当最终结论。

### 1. 产品基础信息

| 字段 | 要问/要判断什么 |
|---|---|
| 产品名称 | 具体是什么，不要只写大类 |
| 站点 | 美国、英国、德国、日本等 |
| 目标价格 | 预期 sale price、coupon、实际到手价 |
| 产品形态 | 单品、套装、补充装、升级款、配件、消耗品 |
| 核心功能 | 解决什么任务 |
| 材质/规格/参数 | 尺寸、容量、数量、兼容、成分、颜色、型号 |
| 目标用户 | 谁买、谁用、什么场景用 |
| 供应能力 | MOQ、成本、交期、包装、认证、可改款能力 |
| 合规风险 | 是否涉及儿童、食品接触、电池、医疗、美妆、安全、商标、专利 |
| 现有资料 | 图片、Listing、竞品 ASIN、关键词、广告、成本表 |
| 卖家精灵文件 | 市场、竞品、关键词、ASIN 反查、CPC、Review 等导出表 |

### 2. 市场与竞品信息

| 字段 | 要判断什么 |
|---|---|
| 核心大词 | 市场入口是否被一个大词控制 |
| 属性词 | 材质、规格、场景、人群、问题词是否丰富 |
| 竞品 Review | 评论壁垒高不高 |
| 竞品价格带 | 低价、中价、高价分别是谁 |
| 竞品页面弱点 | 主图、附图、A+、说明书、FAQ、差评 |
| 广告战场 | Sponsored Products、PT、品牌词、类目页、竞品页 |
| 用户痛点 | Review/Q&A/退货原因反复出现什么 |

## 二、产品画像输出

### 0. 先判断标品/非标品

竞品分析前必须先判断产品类型：

| 类型 | 判断标准 | 分析重点 |
|---|---|---|
| 标品 | 用户主要按规格、型号、参数、兼容、认证、功能购买 | 参数一致、用途一致、价格带、Review 壁垒、供应成本 |
| 非标品 | 用户主要受外观、风格、材质、场景、套装、视觉影响 | 图片相似、产品形态、使用场景、人群、风格、材质 |
| 半标品 | 功能参数重要，但外观、套装或场景也影响购买 | 参数和图片同时看 |

输出格式：

```text
产品类型判断：标品 / 非标品 / 半标品
判断依据：
竞品筛选优先级：
需要人工确认：
```

若用户提供产品图，要先从图片判断产品形态、颜色、材质、数量、结构、组件和使用场景，再进入竞品筛选。不要只按关键词或销量选竞品。

给用户梳理产品时，优先输出这张“产品画像卡”：

| 模块 | 输出内容 |
|---|---|
| 产品一句话 | 这个产品到底是什么 |
| 目标用户 | 谁最可能买，谁不应该作为主线 |
| 核心任务 | 用户买它是为了解决什么任务 |
| 购买触发 | 用户在什么场景下开始搜索 |
| 关键决策因素 | 价格、规格、材质、效果、兼容、外观、便利、信任、Review |
| 主要竞品 | 直接竞品、替代竞品、学习竞品、广告竞品 |
| 差异化方向 | 产品、组合、包装、说明、视觉、价格、广告战场 |
| 首个 SKU 角色 | 入口款、利润款、升级款、防守款、复购款、礼品款 |
| 最大风险 | 合规、供应、价格、Review、广告成本、页面承接、库存现金 |
| 当前结论 | Go / Validate / Hold / No-Go |

## 二-A、竞品选择规则

竞品优先级不是“销量越高越优先”，而是“越相似越优先”。

### 标品竞品优先级

1. 用途一致。
2. 规格/参数/兼容一致。
3. 价格带接近。
4. Review 壁垒可比较。
5. 页面或广告有可攻击弱点。

### 非标品竞品优先级

1. 产品图和形态相似。
2. 使用场景相似。
3. 目标人群相似。
4. 材质、颜色、风格、套装接近。
5. 价格带接近。

### 输出竞品分层

| 层级 | 含义 | 用途 |
|---|---|---|
| 直接竞品 | 和产品最像，用户会直接比较 | 重点拆页面、价格、Review、广告 |
| 替代竞品 | 解决同一任务但形态不同 | 理解用户替代选择 |
| 学习竞品 | 页面、视觉、A+、套装或品牌表达强 | 学习表达和结构 |
| 避让竞品 | 太强、太低价或不是当前阶段能打 | 避免硬碰硬 |
| 剔除样本 | 形态、场景、规格不一致 | 不进入核心分析 |

产品一句话格式：

```text
这是一个面向【目标用户】、用于【使用场景】、解决【核心任务/痛点】的【产品形态】，
主要通过【关键差异】来区别于【主要竞品/替代方案】。
```

## 三、机会判断

### 1. 不能只问“这个品好不好”

要拆成 6 个问题：

1. 需求是否存在？
2. 流量是否能进入？
3. 竞品是否有结构性低效？
4. 产品是否能做出差异？
5. 价格、coupon、广告和成本是否能算通？
6. 团队是否有供应、内容、视觉、广告和现金能力承接？

### 2. 结构性低效检查

| 低效类型 | 表现 | 可转化动作 |
|---|---|---|
| 搜索入口低效 | 大词贵，但长尾属性/场景/痛点词多 | 做 5D 词库，避开硬拼大词 |
| 竞品页面低效 | 主图不清、附图不解释、A+弱 | 用视觉脚本和 A+教育抢转化 |
| 产品形态低效 | 竞品规格、组件、兼容、使用方式不清 | 改产品定义和包装说明 |
| 价格带低效 | 低价品多，高价理由弱 | 证明价值或避开高价硬打 |
| 用户教育低效 | 用户不知道怎么选、怎么用 | 做对比、步骤图、说明书、视频 |
| 广告战场低效 | 竞品只打大词，没有 PT/长尾防守 | 做 ASIN PT、长尾 exact、类目/竞品页测试 |

### 3. Go / Validate / Hold / No-Go

| 结论 | 适用情况 | 下一步 |
|---|---|---|
| Go | 需求、节点、产品定义、毛利、供应、合规基本成立 | 进入上架准备与资产制作 |
| Validate | 有机会，但缺关键证据 | 补搜索、竞品、VOC、成本、合规或广告成本 |
| Hold | 暂时不投入核心资源 | 保留观察，等成本/供应/现金/合规明确 |
| No-Go | 结构性不成立或风险过高 | 记录原因，转其他节点 |

## 四、产品应该怎么做

输出建议时按 5 层给：

1. `产品层`：规格、组件、材质、颜色、包装、说明书、认证、质检。
2. `页面层`：标题、五点、主图、附图、A+、视频、FAQ。
3. `词库层`：核心词、属性词、场景词、痛点词、竞品词、否词。
4. `广告层`：Auto/Broad/Phrase/Exact/PT/防守/探索预算。
5. `经营层`：价格、coupon、库存、现金、Review、周会、Go/pivot/kill。

## 五、常见产品诊断结论模板

### 1. 产品能做，但不能按原思路做

```text
这个产品不是完全不能做，但当前打法偏危险。
主要问题不是需求，而是【价格/页面/广告战场/产品定义/合规/供应】没有承接。
建议先把【节点】缩窄到【具体人群/场景/规格】，再用【词库/竞品/VOC】重做产品定义。
```

### 2. 产品适合先验证，不适合直接上大货

```text
目前更适合 Validate，不适合直接 Go。
缺口是【关键词相关性/竞品弱点/毛利/供应/合规/Review 壁垒】。
先用 7-14 天补齐证据，再决定是否进入 RFQ、打样和 Listing 资产。
```

### 3. 产品应该 No-Go

```text
建议 No-Go。
原因不是“产品不好”，而是【节点不可进/价格带不支持/合规风险过高/广告成本无法承受/供应无法差异化】。
建议保留反向学习：哪些词、竞品或假设误导了判断。
```

## 六、最终给用户的产品全案结构

当用户要求完整梳理时，按这个结构输出：

1. 产品画像。
2. 市场与节点判断。
3. 竞品与结构性低效。
4. 用户/VOC 与购买决策。
5. 产品定义与 SKU 角色。
6. 定价、coupon、毛利和预算边界。
7. Listing、视觉、A+、包装建议。
8. 词库结构和页面/广告路由。
9. 广告架构和上线节奏。
10. Day 0-D90 指标与复盘机制。
11. 风险红线与下一步行动清单。
