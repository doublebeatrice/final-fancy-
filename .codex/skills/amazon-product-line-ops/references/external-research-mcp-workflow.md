# 外部检索与 MCP 数据接入工作流

当用户给出关键词、品类、ASIN、产品图、竞品名，或说“你自己去查资料”“接入 MCP 后帮我搜”“按关键词搜索梳理总结”时，读取本文件。

目标：把外部检索、MCP 数据源、网页搜索、Amazon 页面、卖家精灵/Helium10/JungleScout/广告后台导出、截图和用户手头资料，纳入同一套亚马逊产品线分析系统。不是搜完就罗列资料，而是把资料转成市场、竞品、词库、产品定义、广告、定价、风险和下一步动作。

## 1. 能力边界

### 1.1 有工具时

如果当前环境提供 MCP、浏览器、网页搜索、Amazon 数据、卖家精灵数据、表格读取、图片识别或广告后台数据工具，应主动使用这些工具完成：

- 关键词搜索和 SERP 结构观察。
- 竞品 ASIN 收集与初筛。
- 价格、coupon、Review、评分、BSR、广告位、主图/A+ 弱点记录。
- 关键词扩展、ASIN 反查词、CPC/竞价数据识别。
- Review/Q&A/VOC 抓取或摘要。
- Amazon 官方政策、类目规则、广告规则、费用规则核对。
- 数据导出表字段识别、清洗和合并。

### 1.2 没有工具时

如果当前环境没有可用 MCP/浏览器/搜索工具，不要假装已经检索。应明确说明当前无法直接访问该数据源，并改用以下输入：

- 用户提供的卖家精灵/广告后台/Amazon/Seller Central 导出。
- 用户提供的链接、截图、ASIN 列表、关键词列表。
- 用户提供的产品图、样品说明、报价表、库存表。

仍然按本技能的数据盘点、字段识别、竞品筛选、词库路由和运营诊断输出。

## 2. 关键词驱动的检索流程

当用户只给关键词时，按下面步骤做，不要直接给泛泛市场总结。

```text
关键词理解
-> 搜索意图拆分
-> 商品集假设
-> SERP/竞品采样
-> 竞品清洗与分层
-> 关键词扩展与路由
-> 价格/Review/页面/广告战场观察
-> 结构性低效判断
-> 产品机会与风险
-> 需要人工确认的数据
-> 下一步采集计划
```

### 2.1 关键词理解

先判断关键词属于什么：

| 类型 | 示例 | 重点 |
|---|---|---|
| 品类词 | yoga mat, dog bowl | 市场入口、竞品密度、价格带 |
| 属性词 | stainless steel, foldable, waterproof | 产品事实和规格 |
| 场景词 | camping, kitchen, travel | 使用场景和用户任务 |
| 痛点词 | no leak, odor control | 机制、证据和合规风险 |
| 人群词 | kids, elderly, professional | 用户画像和安全边界 |
| 品牌/竞品词 | 某品牌名、ASIN | 合规边界、PT/研究，不写入 Listing |
| 模糊词 | gift, organizer, accessories | 需要拆商品集 |

### 2.2 搜索意图拆分

同一个关键词可能对应多个商品集。必须拆开：

- 用户是在找主产品、配件、替换件、套装还是补充装？
- 用户关注规格、材质、风格、兼容还是场景？
- 关键词下是否混入不同类目和不同使用任务？
- 是否存在品牌词、专利词、认证词、医疗/安全高风险词？

输出：

| 搜索意图 | 商品集假设 | 需要验证 | 风险 |
|---|---|---|---|

## 3. 外部资料来源分级

外部信息必须分级，不同来源承担不同作用。

| 来源 | 可用于 | 不可直接用于 |
|---|---|---|
| Amazon 搜索页 | SERP 形态、价格带、广告位、主图竞争、初始 ASIN 池 | 精确销量和利润结论 |
| Amazon 详情页 | 页面表达、Review、Q&A、A+、包装信息、变体 | 真实成本、后台广告数据 |
| 卖家精灵/第三方工具 | 搜索量、销量估算、关键词、竞品、CPC 线索 | 单独作为最终结论 |
| Amazon Ads 报表 | 广告真实点击、花费、转化、搜索词 | 市场全量需求 |
| Brand Analytics/SQP | 查询、自然点击/购买、份额变化 | 替代广告 ROAS |
| Seller Central 后台 | 费用、库存、促销、政策、账号状态 | 竞品后台数据 |
| Review/Q&A | 用户痛点、反对理由、产品问题 | 全量市场规模 |
| 官方政策/帮助页 | 合规、功能、资格、费用解释 | 类目实操效果 |
| 用户产品图/报价/成本 | 产品事实、毛利、供应约束 | 外部市场需求 |

## 4. 检索时必须采集的字段

### 4.1 关键词层

| 字段 | 目的 |
|---|---|
| keyword | 原始关键词 |
| 站点/语言 | 避免混站点 |
| 搜索量/ABA/SFR | 判断入口大小 |
| CPC/建议竞价 | 判断广告成本 |
| 相关性 | 强/中/弱/冲突/无关 |
| 词型 | 品类/属性/场景/痛点/人群/品牌/噪音 |
| 商品集 | 属于哪个用户任务 |
| 页面路由 | 标题/五点/A+/后台/图片/FAQ/不用 |
| 广告路由 | Auto/Broad/Phrase/Exact/PT/否词 |
| 风险 | 合规、品牌、误导、不可承接 |

### 4.2 竞品层

| 字段 | 目的 |
|---|---|
| ASIN | 样本 ID |
| 标题/品牌 | 产品身份和品牌壁垒 |
| 图片/形态 | 判断非标品相似度 |
| 价格/sale price/coupon | 价格带和到手价 |
| Review 数/评分 | 信任壁垒 |
| 月销量/销售额估算 | 市场结构线索 |
| BSR/类目 | 类目归属 |
| 变体/套装/补充装 | 清洗商品集 |
| 主图/附图/A+弱点 | 页面攻击点 |
| 差评痛点 | 产品和页面机会 |
| 广告位/自然位 | 战场判断 |
| 竞品类型 | 直接/替代/学习/广告/避让/剔除 |
| 数据日期 | 防止过期 |

### 4.3 广告与经营层

| 字段 | 目的 |
|---|---|
| campaign/ad group/target | 看广告结构 |
| match type | 看探索/验证/收割分工 |
| impressions/clicks/CTR | 看曝光与点击 |
| CPC/spend | 看流量成本 |
| orders/sales/CVR | 看转化 |
| CPA/ACOS/ROAS/TACOS | 看效率和经营压力 |
| coupon 领取/核销 | 看优惠是否有效 |
| sessions/unit session % | 看页面转化 |
| inventory/可售天数 | 看能否放量 |
| cash/补货预算 | 看现金门控 |

## 5. 搜索结果到分析结论的转换

### 5.1 不要输出“资料堆”

搜到资料后必须转成下面几类判断：

| 资料 | 要转成的判断 |
|---|---|
| 搜索页产品很多 | 商品集是否混杂、直接竞品是否清楚 |
| 价格分布 | 目标价格是否能被接受，是否有利润空间 |
| Review 壁垒 | 新品是否能进入，是否需要避让 |
| 主图同质化 | 是否有视觉识别机会 |
| A+弱/说明弱 | 是否有教育和信任机会 |
| 差评集中 | 产品改进、包装、说明书和页面承诺 |
| CPC 高 | 广告战场是否可承受，是否要转长尾/PT |
| coupon 普遍 | 是否必须纳入到手价和毛利测算 |
| 关键词分散 | 是否有多入口机会 |
| 关键词单一 | 是否一词定生死，需要谨慎 |

### 5.2 结构性低效判断

## 6. MCP/工具检索 SOP

如果有 MCP 或工具可用，按这个顺序：

1. `确认关键词和站点`：没有站点时默认询问或按用户背景暂定，但要标注。
2. `搜索关键词`：采样前 1-3 页，记录广告位、自然位、价格、Review、主图形态。
3. `提取候选 ASIN`：先保留原始池，不急下结论。
4. `清洗商品集`：按产品形态、规格、场景、主/配/补充装、价格带拆分。
5. `判断标品/非标品`：决定竞品相似度权重。
6. `筛直接竞品`：优先相似，而不是优先销量。
7. `扩关键词`：按品类、属性、场景、痛点、人群、品牌、噪音分组。
8. `查 Review/VOC`：提炼痛点、反对理由、质量问题和页面缺口。
9. `查政策/合规`：高风险类目必须核对官方或用户后台。
10. `输出人工确认表`：让用户确认产品事实、竞品、关键词和风险。
11. `进入全链路分析`：产品定义、Listing、广告、定价、上线计划。

## 8. 检索质量自检

完成检索梳理后，必须自查：

- 是否明确站点和日期。
- 是否区分原始证据和分析结论。
- 是否把商品集混在一起。
- 是否先判断标品/非标品。
- 是否只按销量选竞品。
- 是否记录 coupon、Review、价格和广告位。
- 是否把关键词路由到页面/广告/否词。
- 是否把 CPC、CVR、CPA、毛利和库存现金连起来。
- 是否标注政策/费用/后台功能需要进一步查证。
- 是否输出人工确认表和下一步采集计划。

如果这些做不到，应补充检索或降低结论置信度，不要强行给 Go。
