# 亚马逊产品线全链路运营技能

## 这个技能是什么

这是一个面向亚马逊产品与运营的中文执行型技能。它不是把手册原文逐字塞进上下文，而是把手册中的底层经营逻辑、门控问题、数据字段、判断顺序、风险边界和动作 SOP 沉淀成可调用的知识库。

调用本技能时，默认把亚马逊运营视为一套连续系统：

```text
产品线方向
-> 市场/节点/商品集
-> ASIN/竞品/VOC/词库证据
-> 产品定义/RFQ
-> 定价/coupon/毛利/现金
-> Listing/视觉/A+/包装
-> 广告与上线
-> Day 0-D90 数据经营
-> 周会复盘
-> 扩品或 Go/Fix/Hold/Pivot/Kill
```

除非用户明确只问某一块，否则不要孤立地回答“广告怎么调”“标题怎么写”“这个词能不能投”。先判断它位于全链路哪一段，再把上游证据和下游影响连起来。

## 覆盖声明

本技能已经覆盖手册中的主要底层逻辑：D-60 到 D90 时间线、七道门控、定方向、市场雷达、结构性低效、节点/商品集、ASIN 池、5D 词库、竞品库、VOC、产品定义、RFQ、定价/coupon/预算、Listing、视觉、包装、广告、上线、Vine/Creator、促销、周会、Brand Store、RACI、诊断矩阵、调价记录、Go/Pivot/Kill 和合规红线。

注意：

- 它不是手册全文的逐字副本；逐字复刻不适合做技能，会让调用成本过高。
- 它保留的是“以后实际分析产品、检查运营、处理数据时必须用到的操作逻辑”。
- 对政策、费用、广告后台功能、Vine、coupon、Deal、类目限制、图片规范、Review 规则等强时效内容，必须以当前 Amazon 官方后台或用户提供的最新截图/链接为准。
- 如用户问“明年”“最新政策”“2027 是否变化”，必须先核对当前规则，再标注 `保留 / 修改 / 新增 / 删除或弃用 / 待查`。

## 核心底层逻辑

1. 产品线优先于单品。不要因为一个 SKU 热卖就盲目开发，要先判断它在产品线中承担入口、标准、利润、升级、防守、复购还是礼品角色。
2. 市场不是大词。大词只能证明需求存在，不能证明新品能进入，也不能证明毛利能成立。
3. 节点是决策对象。节点由用户任务、产品集合、价格带、竞品环境、搜索入口和进入假设组成。
4. ASIN 池只是证据层。必须清洗父子 ASIN、变体、套装、补充装、配件、不同商品集，不能直接把高销量 ASIN 当开发方向。
5. 竞品先分标品/非标品。标品优先参数和用途，非标品优先图片、形态、风格、场景和购买动机。
6. 词库是路由资产。每个词要决定进页面、进广告、进否词、进视觉、进产品定义，还是暂不使用。
7. VOC 要翻译成动作。差评、Q&A、用户语言要落到产品、页面、包装、说明书、FAQ、广告和售后。
8. Listing、视觉、包装必须一致。页面承诺、图片表达、包装信息和说明书不能互相打架。
9. 广告不是买词，而是选择战场、验证流量和分配预算。广告不能替代产品定义、页面信任、价格结构和库存现金。
10. ACOS 是结果，不是原因。ACOS 高时必须联动 CTR、CVR、CPC、CPA、TACOS、coupon、自然流量、库存、现金、Review 和数据置信度。
11. 时间节点是门控，不是机械日期。D-60、D-30、D0、D7、D30、D60、D90 都是经营判断点。
12. 周会不是报数，而是把数据变成动作。每个动作要有负责人、原因、窗口、指标和回滚条件。

## 默认执行算法

当用户提供产品、图片、ASIN、表格、关键词、广告报表、Listing、截图或一批混合资料时，按这个顺序工作：

1. `数据盘点`：列出收到哪些文件、识别出哪些字段、日期和站点是否清楚、哪些能直接用、哪些要人工确认。
2. `产品识别`：根据产品图/链接/描述提取产品形态、材质、规格、组件、场景、用户、风险。
3. `标品/非标品判断`：先判断购买决策逻辑，再决定竞品筛选优先级。
4. `竞品池清洗`：直接竞品、替代竞品、学习竞品、广告竞品、避让竞品、剔除样本分开。
5. `市场与节点判断`：不要只看大词；看多入口需求、结构性低效、价格带、Review 壁垒、供应/现金约束。
6. `VOC 与用户画像`：把差评、Q&A、用户语言翻译成产品、文案、视觉、包装、说明书和广告动作。
7. `词库路由`：每个词判断相关性、词型、意图、页面位置、广告匹配、否词动作和毛利边界。
8. `产品定义/RFQ`：把节点语言翻译成产品九字段、SKU 角色、供应链可实现要求。
9. `定价/coupon/现金`：计算贡献毛利、Breakeven CPA/CPC，判断 coupon、预算、库存和现金能否承接。
10. `Listing/视觉/包装`：检查标题、五点、主图、附图、A+、视频、包装、说明书是否一致。
11. `广告与上线`：搭建探索、验证、收割、防守、修复预算池，不把所有词混在一起。
12. `数据联动复盘`：用 CTR、CVR、CPC、CPA、ACOS、TACOS、coupon、库存、现金、Review、SQP 一起判断。
13. `门控结论`：给 Go / Validate / Fix / Hold / Pivot / No-Go / Kill，并说明证据和缺口。

资料不足时，不要只说“请补充资料”。先给低置信初判，再列出最少补充清单。

## 外部检索与 MCP 接入规则

当用户只给关键词、品类、ASIN，或要求“你自己去查资料”时，必须先判断当前环境是否有可用的内部证据源：selection、SIF、广告后台、sellerinventory、Amazon 前台、GBrain；MCP、浏览、网页搜索、卖家精灵或其他外部工具只作为补充。

有工具时：

1. 明确关键词、站点、日期和数据来源。
2. 先搜索并建立原始证据池，不急下结论。
3. 拆分搜索意图和商品集，避免把不同产品形态混在一起。
4. 先判断标品/非标品/半标品，再筛竞品。
5. 竞品优先按产品相似度、参数/形态、场景和价格带筛选，不只按销量。
6. 把关键词分成页面词、广告词、PT 目标、否词、待确认词。
7. 把价格、coupon、Review、广告位、CPC、页面弱点、VOC、合规风险转成可执行动作。
8. 输出人工确认表，再进入产品定义、Listing、广告和上架计划。

没有工具时：

1. 不要假装已经检索。
2. 说明当前无法直接访问该数据源。
3. 要求用户提供广告后台/Amazon/Seller Central 导出、截图、链接、ASIN、关键词表，或卖家精灵等外部导出作为 fallback。
4. 仍按数据盘点、字段识别、竞品筛选、词库清洗和全链路诊断输出低置信初判。

完成检索后必须自检：是否明确站点和日期、是否区分证据和结论、是否混淆商品集、是否记录价格/coupon/Review/广告位、是否把关键词路由到页面/广告/否词、是否标注政策待查项。

## 分析前提条件

完整分析一个亚马逊产品前，默认使用“产品图/链接 + selection/SIF/sellerinventory/广告后台/GBrain 内部证据 + 少量人工确认”。只有内部证据无法覆盖、且用户已经提供外部导出时，才把卖家精灵等文件作为 fallback；只有没有任何可用导出或快照时，才要求用户手填完整模板。

最低可分析输入：

1. 产品是什么：名称、站点、价格、规格、图片/链接、目标用户、供应成本。
2. 市场是什么：核心关键词、目标价格带、主要竞品 ASIN、需求和场景。
3. 竞品怎么样：价格、Review、评分、主图/A+弱点、差评痛点、广告位置。
4. 关键词怎么样：关键词、搜索量/ABA/SFR、相关性、词型、CPC、页面/广告路由。
5. 广告成本怎么样：预估 CPC、竞品广告位置、目标 CPA/CVR、预算边界。
6. 经济性怎么样：产品成本、FBA/佣金/头程、coupon、毛利、库存和现金约束。
7. 合规风险是什么：认证、专利/商标、类目限制、Review/Vine/coupon/图片宣称风险。

减少手填时，优先让用户提供：

1. 产品图片、产品链接或样品说明。
2. 内部 selection/SIF/广告后台/sellerinventory 快照；卖家精灵导出的市场、竞品、关键词、CPC、Review 数据只作为 fallback。
3. Amazon Ads 搜索词报表、targeting 报表、campaign 报表。
4. 成本、库存、补货、现金约束。
5. 少量人工确认：目标站点、目标售价、产品成本、不可碰风险。

## 竞品分析强制规则

竞品分析前必须先判断产品是 `标品`、`非标品` 还是 `半标品`。

| 类型 | 分析重点 | 竞品优先级 |
|---|---|---|
| 标品 | 规格、型号、功能、兼容、认证、参数 | 用途一致、参数一致、价格带接近、Review 壁垒可比 |
| 非标品 | 外观、风格、材质、套装、场景、人群、视觉感知 | 图片/形态相似、场景相似、人群相似、风格材质接近 |
| 半标品 | 功能参数重要，但外观、套装或场景也影响购买 | 参数一致 + 图片相似 + 场景一致 |

若用户提供产品图，优先基于图片判断产品形态、关键属性和视觉相似度，再从 selection/Product Time Machine/SIF/Amazon 前台竞品池里筛选相似竞品；卖家精灵竞品池只作为外部补充。不要只按关键词或销量选竞品。

## 广告与数据联动强制规则

当用户问广告优化、ACOS 高、广告花费高、关键词不出单时，必须遵守：

1. 先判断数据置信度：样本量、归因窗口、日期、是否刚改页面/价格/coupon/bid。
2. 再判断流量相关性：搜索词、ASIN、属性、场景、产品形态是否匹配。
3. 再看漏斗：曝光、CTR、CVR、CPC、CPA、ACOS、TACOS。
4. 再看页面和 offer：主图、标题、价格、coupon、Review、A+、FAQ、配送、库存。
5. 再看财务：Breakeven CPA/CPC、贡献毛利、coupon 后毛利、退货。
6. 再看库存现金：库存黄/红或现金黄/红时不能盲目放量。
7. 最后给动作：保留、观察、迁移 exact、降 bid、隔离、否定 exact、否定 phrase、修页面、调 coupon、重构预算池。

不要输出“ACOS 高就降预算/否词”这种单指标结论。必须说明 ACOS 高背后的原因链。

## 时效知识规则

本技能知识基线日期为 2026-06-17，来源手册发布时间约为 2026-06-07。经营框架可复用，但平台政策属于强时效内容。

当用户问“最新”“明年”“2027”“政策变了”，或准备真实上线、促销、合规执行时，不能默认 2026 年规则仍有效。应优先核对当前官方规则或要求用户提供后台截图/政策链接，再用下面标签更新判断：

- `保留`：底层方法仍有效。
- `修改`：方法仍有效，但政策、阈值、功能、费用或资格条件变化。
- `新增`：需要加入新的功能、费用、报表、门槛、风险检查。
- `删除/弃用`：旧动作不再允许、不可用或风险过高。
- `待查`：无法确认，必须进一步查证。

## 推荐输出结构

分析类任务优先按下面结构回答：

1. `阶段判断`：用户现在处于全链路哪一步。
2. `已收到资料`：文件、字段、日期、站点、可用性。
3. `数据置信度`：低/中/高，为什么。
4. `关键判断`：3-7 条高信号结论。
5. `证据缺口`：决策前还缺什么证据。
6. `建议动作`：按顺序给出步骤，必要时标注负责人、输出物、观察窗口、回滚条件。
7. `门控结论`：Go / Validate / Fix / Hold / Pivot / No-Go / Kill。

