# Long-Term Memory

This file keeps durable operating memory for future Codex sessions. Prefer this over dated handoff notes when a detail affects future decisions.

## Operating Boundary

- The deciding AI session is the AI decision entry point. Either Codex or Claude fills that role for a given run; both are peer operator-facing CLI sessions.
- The extension panel and Node scripts collect data, export snapshots, validate schemas, execute APIs, verify landing, write notes, and summarize results.
- Do not add an AI provider, model runtime, or second strategy layer inside the panel.
- Action schemas must carry `approvedBy` set to `codex`, `claude`, or `manual` to clear the executable gate (see `src/ai_decision.js`).
- If the decision is not safe from current context, emit `review` instead of using hidden rule fallbacks.

For each SKU in scope, treat it as a complete advertising operations package, not a single bid edit or one ad-group test. The workflow must cover SKU-level sales/order/profit or margin context, inventory days, season window, `/product/chart` impressions/clicks trend, `/product/adSkuSummary`, `/product/adProductData`, SP auto, SP keyword, SP manual target, SB keyword, SB target, campaign/product-ad state, paused but potentially valuable entities, campaign budget, placement/top-of-search, weak traffic waste, and listing-session/conversion/listing readiness. - When the user asks about a concrete SKU, do not default to a full snapshot export. - Never store hard-coded `x-xsrf-token` values. Single-SKU ad fetches must execute inside the logged-in `adv.yswg.com.cn` debug tab and use the browser session/cookie.
- Interface selection rule: named SKU overall health starts with `/product/adSkuSummary` via `node scripts\execute\fetch_ad_sku_summary.js <siteId> <days> <SKU>`; named SKU ad-row breakdown uses `/product/adProductData` via `fetch_sku_ad_product_data.js` and can include `dailyBudget`; specific SP/SB ad-group rows use `fetch_ad_group_rows.js` for `/keyword/findAllNew` with local `campaignId + adGroupId` filtering; campaign placement uses `fetch_campaign_placement.js` for `/placement/findAllPlacement`; specific SP ad-group internals use `fetch_sp_group_detail.js` for `/advTarget/findManualProductTarget` and `/customerSearch/targetFindAll`; full snapshot is for cross-SKU pool discovery/prioritization only.

- Per-product full operating framework: apply the complete operating analysis to every product, not only large-decline or focus products. The SKU's stage, priority, inventory pressure, profit impact, and window timing decide the depth and action strength, but the diagnostic order is the same: business total view, listing readiness, ad structure, traffic trend, best-performing ad form, placement, B2B/business fit, search-term drilldown, executable actions, manual tasks, risk reminders, and observation plan.
- Product tag rule: use short tags to make the current operating status visible, but choose the tag from facts. Examples include `大下滑｜高库存｜利润影响大｜需补流`, `高转化｜低曝光｜可补流`, `库存紧｜控放量`, `低效消耗｜需控费`, `结构缺口｜需补组`, `Listing承接弱｜先修复`. Tags are reminders, not fixed action rules.
- Ad-system workflow for every SKU: after opening the ad system, inspect enabled ad structure in this order: SP keyword, SP auto, SP product/ASIN targeting, SB/SBV, B2B auto, and B2B keyword. Then judge traffic expansion space: broad-to-phrase/exact expansion, converting search-term extraction, ASIN targeting expansion, B2B auto/keyword fit, and SB/SBV coverage. If the current tools cannot create SB/SBV/B2B or another required ad type, explicitly list it as manual work; never imply it was completed.
- Traffic trend rule for every SKU: read 7/15/30-day impression and click trends and identify which ad types supply the impressions/clicks. For peak/preheat or strategically important SKUs, weak or declining impressions/clicks can make traffic repair and structure completion more important than spend cutting. For off-season, low-fit, or low-profit SKUs, the same trend can justify controlled spend reduction. Do not judge from ACOS alone.
- Performance rule for every SKU: rank ad forms by orders, ACOS/ROAS, impressions, clicks, CPC versus recommended/average CPC, and room to scale. If auto is the best order source, consider additional auto structures, B2B auto if product fit supports it, and controlled bid tests near reasonable CPC. If keywords have low impressions, investigate keyword coverage, bid, match type, and group rebuild. If product targeting has low impressions, inspect ASIN coverage and targeting bid. If SBV/SB carries meaningful impressions, consider more SB/SBV coverage or manual creation if automation cannot do it.
- Search-term drilldown rule: every converting ad group must be drilled into customer search terms before finalizing the SKU decision. Identify converting terms, high-click no-order terms, acceptable-ACOS terms, broad terms worth promoting to phrase/exact, terms to add to old or new groups, and terms to lower, pause, or negate. Do not leave good converting search terms trapped only inside the original broad/auto group when separate price control or scale is justified.
- Placement must be part of each focus-SKU analysis. Check Top of Search, Product Pages, and Rest of Search separately: impressions, clicks, conversion, CPC, ACOS, and whether the placement deserves higher/lower adjustment. If Top of Search converts materially better and the SKU is in-window with inventory and historical sales support, a controlled Top of Search increase can be a traffic repair lever. If Product Pages converts well, combine with ASIN targeting expansion. If a placement gets clicks but no conversion, do not simply raise bids; judge position quality and relevance. If ACOS is badly out of control and there is no inventory/window reason, do not raise placement.

6. Review sales, inventory, YoY, spend, orders, ACOS, and the personal trend abnormal pools before deciding.
7. Run the season gap audit and review high-inventory active-season SKUs before closing the day.
