# 低效词管理固定流程

> 2026-06-23 最终定稿。推翻了早先"自己算保本线 max(净利,30%)"的版本。

## 为什么跟后台红色走

试图纯机械按一个 ACOS 数字判，怎么都对不上用户手调。让用户先全量过一遍 330 词、再回读后台 diff，发现：用户降的词 ACOS 中位 38%、留下不碰的词 ACOS 中位 36%——两个数贴死，单靠 ACOS 数字切不出他心里那条线。追问之下用户点破：他判超线不是心算百分比，是看后台那个 ACOS 数字标没标红。

决定性证据：同一个 ACOS 值 `39.15%`，在一个产品行是红 `rgb(255,0,0)`、在另一个产品行是灰。红线不是固定 ACOS 数，是每个产品自己一条线——后台拿该产品利润率当线，ACOS 越过它自己的线就标红（广告后台 row 的 `processRemark` 里后台自写规则印证：比的是 `acos vs 毛利率`）。红是后台每天按最新产品利润实时重算的，我们不用自己拉利润算线，照红做动作即可。

## 固定规则（跟红色走 + 出单缓刑）

先看 ACOS 数字红不红，红了再按"有没有出单 / ACOS 多高"分流：

1. **红 + 出单 + ACOS < 50%** → 只降一档（=当前出价 15%），永不停。出单是缓刑，再红顶天就是降。
2. **红 + 出单 + ACOS ≥ 50%** → 停。出单也救不回——ACOS 到 50% 是卖一单亏太多，用户拍板"出单也停"。
3. **红 + 没出单（纯浪费）** → 降一档；已降到地板（0.02~0.05）还在烧 → 停。
4. **出价已到地板再降不动** → 停（降无可降）。
5. **没红** → 一律不碰。
6. **核心词 / 要打展示的线**（铁律，压过 1~4）→ 红了、ACOS 再高也只降不停。已知保护名单：galvanized flower bucket(DN2108)、silicone cord ties(TH2619)。打展示在售 SKU 同此规则。保护名单后续发现新的往里加。

## 出单缓刑解释

早先误记成"出单就保护只降不停"，用户纠正"出单也要看 acos，100acos 出单也不行"。实测今天手调印证：他留的有单词 ACOS≤85%，停的有单词有 72/111/127%。所以 ACOS 仍是老大，出单只让动作从"停"缓成"降"，但 ACOS≥50% 连缓刑都没有。

## 怎么读红

试过用手里的利润字段反推后台红线公式（红=acos>k×利润，试了 net_profit/busy_net_profit/profitRate × 0.8~1.5），最高只对上用户手调的 49%——后台算红用的利润口径离线拿不到，反推不可靠，已放弃。

唯一可靠做法：程序把 KeywordManage 页一屏屏翻到底，直接读每个 ACOS 单元格颜色（纯红 rgb(255,0,0)），读到的就是后台 painted 的真红、跟用户眼睛一致、零误差。注意读屏要在程序独占控制翻页时做，别在用户正操作页面时读。

## 其他规则

- 自动组不特殊：自动组和别的词一样处理，没有特殊待遇。
- 数据来源：售价 `min_price` 直接在广告后台 `/keyword/findAllNew` 每行自带，不必再单独跑库存后台。词→产品靠广告活动名末尾 SKU token 提取。
- 冷却：6 天内调过的不碰。
- 唯一带单词若 ACOS≥50% 仍会停（除非在核心/打展示保护名单）。"唯一带单"本身不再是免死金牌。
