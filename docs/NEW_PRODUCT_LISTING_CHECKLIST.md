# 新品 listing 开工清单（一条线走完，不回头）

这份清单的唯一目的：把写新品 listing 从"靠记性"变成"照着走"。每步标了 **谁干 / 算"真完成"的标志 / 坑在哪 / 对应闸**。

权威来源：`D:/ad-ops-brain/playbooks/new-product-listing-writing.md`（22 步）。本清单是它的执行版，外加现场踩出来的"填了值≠做完"坑。

落地闸命令：`npm run ops:listing:gate -- --product-id <id> [--sku <SKU>]`
它会开一个全新审核页（新 tempid），把坑字段从**实时后台**读回来，逐条判 PASS/FAIL。**它绝不替你翻「关键词已填」提交那一步。**

---

## 核心心法（这次绕弯的根因）

后台很多字段是 **「填了值 ≠ 做完了」**：你只往隐藏 input 塞值、不走它自己的弹窗/按钮/单选+保存，前台就是空的、后台也没真关联。下面四个坑全是这一条：

| 坑 | 错误做法 | 正确做法 | 闸 gate key |
|----|---------|---------|------------|
| 上传类别 | 塞 `variant_select1` 的值 | 点开「上传类别」弹窗，两级下拉选完，**保存** | `category` |
| Search items | 填进去 242 字就算完 | 点页面**「格式化」**按钮，系统去重压缩 | `search` |
| 已核对 | 改 radio 的 `checked` | **真点 layui 单选**触发联动翻「是」 | `pack` |
| 保存成功 | 看到"保存成功"就收工 | 开**新 tempid** 审核页回读，读同一个 iframe 是自指的 | 全部 |

## 阶段 0 ｜ 先确认身份（别急着写字）

- [ ] 从"关键词未填"列表拿 SKU → 审核列表搜 → **最下面那条是母体**（看位置，不看字段名）。【你/我】
- [ ] 用户说只做单个就只做单个，不顺手写整组变体。【约束】
- [ ] 进审核详情，**先看装箱数**：单品=当前数量；组合无主次=整体；有主次=主品；套装=套数。**不对先问开发，别自己改。**【开发拍板】

## 阶段 1 ｜ 核对事实（以图为准）

- [ ] 产品图 + 中文产品信息 + 开发原标题/参考卖点 三者对齐：形状/数量/材质/尺寸。开发没留参考文案≠异常，自己写。【我】
- [ ] **上传类别**：选这个产品**自己对应的相近类别**（玩具选玩具、厨房选厨房，每个产品不一样）。
      ⚠️ 坑：必须点开「上传类别」弹窗，在两级下拉里选完再保存。光塞隐藏 input 前台是空的。→ 闸 `category`【我】

## 阶段 2 ｜ 拉证据再埋词（顺序不能反）

- [ ] 先拉市场证据：SIF / 选品系统 / 竞品前台词 / 长尾。Amazon 下拉词只能当低优先级启发，得二次验证。【我】
- [ ] 写广告三类词（核心 / 低竞争 / 长尾）。→ 闸 `adv`【我】
- [ ] **US 商标类别 + 小类编码**：⚠️ 只填类别漏小类 = 没填全，常规补 6 位。→ 闸 `register`【我】

## 阶段 3 ｜ 写文案主体（我该干的核心）

- [ ] 标题：**数量靠前**，再品类再场景。改了开发原标题要说明改哪、为啥。→ 闸 `title`【我】
- [ ] Product Description 用当前模板：Features / Specifications / Package includes / Notes，新卖点自然埋词。→ 闸 `pd`【我】
- [ ] Search items 按重要性排、控长度。⚠️ **必须点页面「格式化」**，系统会去重压缩。→ 闸 `search`【我】
- [ ] 装箱数核对完 → ⚠️ **已核对**单选要**真点 layui 单选**翻「是」，只改 checked 无效。→ 闸 `pack`【我】

## 阶段 4 ｜ 合规 + 风险（保存前最后一道）

- [ ] 看商标查询。分类下不能写的商标词从标题/卖点/描述/search 移除；保留高风险但重要的词，**用中文**在备注说明为什么不能去（通用表述/前台普遍用/Google 无单一指向）。Edit Record 非挂靠场景留空。【我】
- [ ] **竞卖品牌名**：填真实竞品品牌（实时从 Amazon 拉，不编）。→ 闸 `competitor`【我】
- [ ] 有大改动/删 IP 词/产品信息不一致 → **先给用户一段可转发开发的话术**（开发名+SKU+问题+风险+建议），再保存。【我→你→开发】

## 阶段 5 ｜ 保存 → 落地 → 回读（这步才是"完成"）

- [ ] 保存。遇到：`敏感词检测中`→等检测完重存；`CPC玩具弹窗`→继续保存；`必填项不能为空但其实不空`→重渲染表单再存一次。【我】
- [ ] 跑闸：`npm run ops:listing:gate -- --product-id <id> --sku <SKU>`。**所有文案主体 gate 必须 PASS**，否则 BLOCKED，补完再来。【我】
- [ ] **关键词状态翻「已填」** —— ⚠️ 用真实 layui 单选点击，不是改 checked。**这步=正式提交，你拍板。**→ 闸 `submit`【你】
- [ ] 翻完再跑一次闸，确认 `submit` = DONE（已提交并回读到时间+填写人）。【我】
- [ ] 回审核列表确认"关键词已填 + 时间"，回详情确认标题/PD/search 没被旧页面覆盖。【我】

## 边界（省得每次问）

- **我填**：标题、卖点、PD、search items、广告三类词、商标类别+小类、竞卖品牌名、文案优化思路。
- **开发/选品的，我不编**（闸里标 INFO，不卡保存）：装箱数、运输安全等级、体积重、市场分析（要 TOP5 利润率）、竞品同款/相似款链接（选品判断选哪几个卖最好）。空着不卡保存时我报给你，不糊。→ 闸 `dev_market` `dev_seller`
- **你拍板**：最后翻「关键词已填」=提交。

## 闸判定含义

- `PASS / ❌FAIL / ⚠️WARN`：文案主体字段。有 FAIL = BLOCKED，退出码 2。
- `ℹ️INFO`：开发/选品字段，只报不卡。
- `🟢DONE / ⏳PENDING`：提交状态，本工具只读不翻。
- 判定 `READY TO SUBMIT`：文案全绿，可以翻提交了（你拍板）。
- 判定 `SUBMITTED & VERIFIED`：已提交并独立回读到。
- 判定 `BLOCKED`：有坑没真落地，列出来补完。
