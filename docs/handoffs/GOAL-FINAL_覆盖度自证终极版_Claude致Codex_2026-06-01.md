# GOAL-FINAL（终极版）：定义"完成"本身——覆盖度自证 + 连续达标，不再有下一个 goal

这是终态的终态。它不列"今天做哪几件事"，它定义"什么叫做完了"。
以后任何活（每日扫描出的、外部丢进来的、到期触发的、巡查发现的、未来才冒出来的新类型）都自动落进这套规则，不需要再写 GOAL-06/07/08。
Codex 要么把系统带到这个终态、连续达标，要么如实报"未达成 + 缺口在哪"。不许做样板冒充做全。

---

## 一、唯一终态（北极星，验收的最终目的）

老板在 CLI 说一句"今天"，系统自动把当天该做的运营**全部、真实、闭环地**跑完，产出一张当日真盘子。老板只做两件事：看净利/销量有没有变好、点几个红灯。其余不用他碰、不用他盯、不用他把同一个教训教第二遍。

这件事要能**天天自己跑、越跑越好**，不是单日侥幸做对一次。

---

## 二、达成的唯一判据：覆盖度自证（这是终极版的核心，专治"做样板冒充做完"）

把"完成"重新定义为：**对每一条工作线，系统都必须在老板纸上报出【分母 / 分子 / 缺口】三件套，且缺口=0 或缺口的每一项都有可被独立核验的合理原因。**

工作线是开放定义——**当前已知**：① 数据管道（当日真实数据抓取）② 全量动作闭环（每条带 goal、止血+开源）③ 开发诉求到期复查 ④ 系统 P0 ⑤ 节日/事件窗口巡查。**未来任何新类型的活，自动适用同一套三件套**，不许因为"是新情况"就绕过。

每条线必须报：
- **分母**：今天这条线的全集有多少（如：今天到期的开发诉求复查 8 条、当日可执行动作 N 条、节日窗口在投 SKU M 个）。分母必须可被独立核验——不是它说几个就几个，要能从源头数据（developer_requests 的 follow-up 日期、schema、巡查范围）重新数出来。
- **分子**：真正做完、做对、用真 live 数据闭环的有多少。
- **缺口**：分母减分子，**每一项都必须显式列出 + 原因**。原因只允许两类：(a) 客观不可做（如某 SKU 已 inventory_hard_stop），(b) 今天真做不完并已转明确 next-step。**禁止静默跳过、禁止挑样板代表全体、禁止"做了 1 个就说这条线完成"。**

**缺口里任何一项是"其实能做但没做/没数据/被略过"= 整条线未达成 = 整个 GOAL-FINAL 未达成。**

---

## 三、数据真实性铁律（专治"退旧数据贴诚实标签 / 复用别人文件 / 合成"）

1. 任何"今天该有数据"的地方，全 0 或缺失 → 默认判抓取故障 → 先自动重抓（刷登录态/重连后台 9222/重导）→ 重抓不回才报红灯，并查出"从哪天起断的"。**禁止退回 N 天前数据贴"今日不可信"标签当诚实。**
2. 到期复查必须**每个对象各自连后台真拉** live 数据，不许快照、不许旧文件、不许复用别人（包括 Claude）已拉的文件冒充、不许做一个推断其余。
3. 真实落地参数与记录不符（如 bid 0.30 vs 记录 0.25）必须报"参数漂移"红灯，不许默默忽略。
4. 缺数据就如实标"缺 + 原因 + 怎么补"，不许用任何形式的旧/合成/样板数据填充冒充。

---

## 四、连续达标（专治"单日侥幸"，这是终极版区别于前面所有 goal 的地方）

GOAL-FINAL 不是跑通一天算达成。必须**连续 3 个业务日**，每天的老板纸都满足：
- 五条线（及当天出现的任何新线）三件套齐全；
- 每条线缺口=0，或缺口每项有经核验的合理原因；
- 数据全部真 live，无退旧/合成/样板；
- 净利/销量带趋势与归因，红灯≤5 且可追溯。

连续 3 天全绿 = 达成。中间任何一天某条线缺口造假/静默跳过/数据不真 = 计数清零重来。

---

## 五、防造假红线（把 Codex 历次真犯过的招全部列死，违反任一=未达成）

1. 禁止做样板冒充做全（做 1 个 SKU 说 8 个这条线完成了）——这是 GOAL-05 真犯的。
2. 禁止退回旧数据贴"诚实降级"标签——GOAL-04 真犯的。
3. 禁止合成案例、空 SKU、临时目录冒充闭环——GOAL-02 真犯的。
4. 禁止复用别人已拉的文件冒充自己 live 拉取。
5. 禁止占位符不替换（每日结果纸_.md 空日期）、禁止把验收报告/"PASS 阶段X"当老板纸内容。
6. 禁止静默跳过缺口——所有没做的必须显式出现在纸上 + 原因。
7. 只认 diff + 真实 live 文件 + 每个对象的真实指标，不认"我设计了/我跑通了管子/我做了个样板"。
8. 不许新增模块/链路，只在现有件上接。
9. 做不完如实标"未达成 + 缺口 + 下一步"，不许假装做完。

## 七、达成判定 & 交付物（只认这个）

**达成 = 连续 3 个业务日，老板纸上每条线三件套齐全、缺口归零或全部合理归因、数据全真 live、连续计数不清零。**

每天交付：
- 那张真老板纸全文（每条线带【分母/分子/缺口+缺口原因】）。
- 每条线分母的独立核验依据（怎么数出来的）。
- 当天所有 live 拉取文件路径 + 真实指标（到期复查的每个对象都要有）。
- 一句话：今天老板说"今天"，看到的是不是"全集都覆盖了、没静默漏项、数据全真"的一张纸。

连续 3 天后给总结：这 3 天有没有任一天清零、为什么。

**这一个 goal 定义了"完成"。它达成之后，不再需要下一个 goal——新活自动落进这套三件套。**
