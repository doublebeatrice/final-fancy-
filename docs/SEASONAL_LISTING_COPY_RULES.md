# Seasonal Listing Copy Rules

Last reconciled: 2026-05-16.

This document defines the operator-approved rules for seasonal listing title edits. It applies to `copy_edit` listing actions generated by `src/season_title_opportunity.js`, `scripts/generators/generate_season_title_listing_schema.js`, and executed through `scripts/execute/run_listing_copy_edits.js`.

## Execution Boundary

Successful sellerinventory submission means the internal edit application was submitted for review. It is not proof that the Amazon front-end listing has changed.

Seasonal title edits can be auto-submitted only when all of these are true:

- The SKU is not `saleStatus=保留页面`. Reserved-page products preserve the existing product page and must not receive listing copy edits.
- The SKU is not in the top 50 by sales, unless the operator explicitly says to change it.
- The edit is limited to the parent title seasonal/core keyword wording.
- The product-event fit is supported by listing text, product profile, search/core keywords, inventory context, or operator instruction.
- Awareness, heritage, history, Pride, Juneteenth, and similar sensitive/cultural nodes require concrete event words in the product evidence. Generic words such as `month`, `day`, `week`, `party`, `gift`, or `decorations` are not enough.
- The dry-run validator passes with no hard errors.
- Immediately before live submission, sellerinventory `getOriginData` must still match the planned `original[parent_title]`. If the live origin title differs, stop with origin-title mismatch instead of submitting a stale plan.
- If the event has year-specific wording or theme risk, current external evidence has been checked or the title uses a stable evergreen buyer term instead.

Top-50 SKUs must be surfaced as reminders until the operator explicitly says `change` or `do not change`. If the operator explicitly instructs a change, execute it regardless of sales rank after validation.

## Title Writing Logic

Preserve the product identity first. Do not rewrite the front half of a title unless the core product term is wrong or stale.

For variant groups marked as separate-title/differentiated-title in sellerinventory, color or style-specific title edits belong in `title_en` (English title), not `parent_title` (parent title). Use `omitParentTitle: true` in the copy-edit action when the parent title must remain untouched; otherwise sellerinventory can still validate the unchanged parent title together with the child English title and block submission on same-group parent-title locks or combined repeated-word checks.

Preferred seasonal edits:

- Replace expired event wording with a stable evergreen buyer term when supported by product context.
- Append a current buyer-search term only when the title does not already contain an equivalent term.
- Prefer concrete buyer terms over internal calendar labels.

Examples:

- `Cinco de Mayo` on a pinata product after 2026-05-05 can become `Fiesta Party Supplies` or `Fiesta Decorations`.
- `Lab Week Gifts` after 2026-04-25 can become `Lab Tech Gifts` when the listing is clearly for laboratory professionals.
- Internal labels such as `Summer Product Season` must not be written into Amazon titles. Use buyer-facing terms such as `summer party supplies`, `pool party decoration`, `summer outdoor`, or `beach party decorations`, and only when the product has summer/pool/beach/swim/luau/tropical evidence.
- `Easter Eggs`, `Easter Craft Kit`, or other holiday words that are product identity should not be auto-removed merely because the calendar date passed.
- A Black History / Juneteenth product must not be auto-mapped to Mental Health Awareness Month from weak overlap like `Month`. For example, `CAS4030` is a Juneteenth cupcake topper; mental-health wording and mental-health ad campaigns are wrong unless live product evidence explicitly contains mental-health language.

## External Verification

Local calendar data can be stale. Before using event-specific or annual-theme wording, check current sources when the event is time-sensitive, year-specific, or outside stable evergreen retail language.

Stable evergreen cleanup usually does not require annual theme insertion:

- `Cinco de Mayo` cleanup can use `fiesta` / `Mexican fiesta` / `party supplies` terms for fitting products.
- `Lab Week Gifts` cleanup can use `Lab Tech Gifts` / `Medical Laboratory Gifts` for fitting products.

Annual-theme wording should not be auto-inserted into product titles unless explicitly supported and safe. For 2026 Lab Week, current external references include:

- CDC: `Laboratory Professionals Safeguard Health`.
- ASCP / related Lab Week materials: 2026 Lab Week runs April 19-25, 2026, with `Lab Story` / `To Infinity and Beyond for Our Patients` appearing in event materials.

Because annual slogans may be trademarked, campaign-specific, or not buyer-search language, prefer stable buyer terms for cleanup unless the operator asks to test the slogan.

## Product Context And Children Terms

Inventory `productLabels.product_label` is a signal, not an absolute title rewrite rule.

- If the historical title or product context clearly supports `baby shower`, `gender reveal`, or `baby sprinkle`, keep those terms even when inventory says non-children product.
- Existing child/baby terms in the original title are not automatically risky.
- Newly introduced generic child terms such as `kids` or `children` require supporting context; otherwise they produce warnings or review.

## Automatic Review Conditions

Send to review instead of auto-submit when:

- The product sales status is `保留页面`; preserve the current product page and do not submit listing copy changes.
- The SKU is top 50 by sales and the operator has not explicitly approved the change.
- The SKU is listed in `data/listing_copy_protected_skus.json`; this is an extra manual override, not the primary reserved-page signal.
- Current title is missing and sellerinventory origin data has not been fetched.
- Product-event relevance is low and no safe expired-term cleanup exists.
- The proposed term is a broad naked seasonal generic term without exact product support.
- The selected awareness or cultural event is supported only by generic calendar words, not by event-specific product evidence.
- Live sellerinventory origin title differs from the plan's original title, indicating the plan is stale.
- The title contains an event word that may be product identity rather than expired keyword stuffing.
- External current information is needed for an annual theme and has not been checked.
- Backend validation reports duplicate-word, title-length, variant-title, or forbidden-term issues that cannot be auto-repaired safely.

## Current Commands

Generate and dry-run seasonal title opportunities:

```powershell
npm run ops:season-title:dry
npm run ops:season-title:listing-schema
npm run ops:listing-copy
```

Execute a reviewed listing copy schema through the active sellerinventory browser session:

```powershell
node scripts\execute\run_listing_copy_edits.js --schema <schema.json> --execute
```

Query or withdraw a submitted edit application through the active sellerinventory browser session:

```powershell
npm run ops:listing-copy:withdraw -- --id <application_id>
npm run ops:listing-copy:withdraw -- --id <application_id> --execute
```

The withdrawal command must read CSRF/referrer state dynamically from the logged-in browser. Do not paste or persist `inventory-token`, `jwt-token`, `x-csrf-token`, cookies, or copied request headers.

The execution report must distinguish:

- `submitted_pending_review`: sellerinventory accepted a new edit application.
- `covered_by_existing_variant_application`: the SKU belongs to a variant group already covered by a sibling parent-title application.
- `failed`: backend or validation failure requiring triage.
- `deleted`: sellerinventory accepted withdrawal/deletion of an edit application.
